# Code of conduct

## The short version

Be decent. Assume the other person is trying to help. Criticise the code, not
the person who wrote it.

## What that means here

This is a small learning project, so most interaction is about whether
something works and why. That goes better when:

- **Feedback is about the work.** "This loses samples when the WAL rolls" is
  useful. "This is amateur work" is not, and is also less specific.
- **Questions are welcome at any level.** The whole point of the repo is
  learning how these systems work. Nobody gets told to read the source first.
- **Disagreement ends in a decision.** If a design argument is going in
  circles, it becomes an ADR in [`docs/adr/`](docs/adr/) — the alternative gets
  written down as rejected, with the reason, and the discussion is over.

## Not welcome

Harassment, personal attacks, discriminatory language, sustained disruption,
and publishing someone's private information. Also: pull requests that are
mostly an argument about something other than the code.

## Enforcement

Report a problem to the maintainer at
[tuvo1106](https://github.com/tuvo1106) — by private vulnerability report,
email on the GitHub profile, or a DM. Reports stay confidential.

Responses scale with the behaviour: a private word, a public correction, an
edited or deleted comment, or a block from the repository. The maintainer
decides, and applies the same standard to himself.
